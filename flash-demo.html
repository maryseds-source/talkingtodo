This page lets you try one AI model — Gemini 3.1 Flash-Lite — against five kinds of input: text, images, audio, video and PDFs. Every demo does the same job: it looks at whatever you give it and pulls out a structured list of items. The point isn't the list — it's feeling how the same single API call handles completely different kinds of input.

A way to judge any AI feature: the three C's

As you try each demo, evaluate it against three questions. Each demo page repeats these for its own input type.

1. Cost — what does each call cost?

This model charges per token (roughly ¾ of a word). Sending text, images or video in costs $0.25 per million tokens; audio in costs $0.50; the model's answer costs $1.50 per million tokens out. In practice, every demo on this page costs a fraction of a cent per click — which is exactly why this "Lite" model exists: it's Google's cheapest, fastest Gemini, built for high-volume features where cost per call matters more than deep reasoning.

2. Capability — what can it actually do?

This model natively understands text, images, audio, video and documents, and can return answers as structured data (guaranteed-format JSON) instead of chat prose — that's what makes it usable inside an app rather than just a chatbot. It also supports "thinking" (spending extra tokens reasoning before answering), which you can turn up when quality matters more than speed. It does not generate images or audio, and doesn't support real-time voice conversations — those need different models.

3. Context — how much can it consider at once?

The model can take in about 1 million tokens per request — roughly 8 novels of text, an hour of video, or several hours of audio. The practical limit in this demo is usually the upload, not the model: files sent straight from the browser should stay under ~15 MB. Bigger inputs are possible with a slightly different upload method (noted in each demo).

Text

The simplest possible AI call: words go in, structured data comes out. The model reads whatever you paste and returns a clean list of items — not a chatty paragraph — because we tell it the exact JSON shape we want back.

Try this: paste something messy — a rambling email, a recipe, meeting notes, or "we need milk, that thing for the school fair, and dad's birthday present" — and watch it come back as tidy items with categories.

Text
How this works

One API call happened: your text was wrapped in a short instruction (“Extract distinct items from this text”) and sent to the model, along with a response schema — a contract saying “you must reply with a list of items, each with a name, category and details.” The model can't reply with prose; it has to fill in that shape. That's the difference between an AI feature and an AI chatbot.

Things you could change to tune this:

  • The prompt — ask for tasks instead of items, or add rules like “ignore anything already done.”
  • The schema — add fields like priority or due_date and the model will fill them in.
  • Thinking level — this model can be told to reason more (minimal / low / medium / high) before answering. More thinking = better answers on tricky input, but slower and more output tokens.
  • Temperature — how creative vs. consistent the answers are (0–2; extraction jobs like this want it low).
Cost
A page of text in + the list out ≈ 1,000 tokens ≈ $0.0005. You could run this ~2,000 times for $1.
Capability
Structured output (guaranteed JSON), instruction following, optional thinking for harder extractions.
Context
Up to ~1M tokens per request — you could paste entire books, not just notes.

Image

The same call as the Text demo, but now the “text” is a photo. The model looks at the image directly — there's no separate photo-recognition service involved. One model, one call, different input.

Try this: photograph your fridge shelf, your desk, a handwritten list, or a receipt. Handwriting and cluttered scenes are the interesting test — that's where you learn what it can and can't see.

Tap to take a photo or choose an image
How this works

Your photo was converted to a block of encoded data in the browser and attached to the request alongside the instruction “identify and list all distinct items visible in this image.” The model reads pixels the way it reads words — an image is just turned into tokens (roughly 250–1,000 of them depending on size) and considered together with the prompt.

Things to consider when evaluating an image feature:

  • Prompt specificity matters more with images — “list the food items, ignore packaging and brands” gives very different results from “list everything you see.”
  • You can send several images at once (up to 3,000 per request) — e.g. “compare these two pantry photos and list what's run out.”
  • Accuracy limits — it's excellent at reading text in photos and naming objects, weaker at precise counts (“exactly how many eggs”) and fine spatial detail.
Cost
A photo ≈ 250–1,000 tokens ≈ $0.0003 per image. Analysing 1,000 photos costs about 30 cents.
Capability
Native vision: objects, scenes, handwriting, text-in-photos (receipts, labels, signs). Understands images; can't create them.
Context
Up to 3,000 images per request; ~7 MB per image sent this way. The whole request must fit the 1M-token window — images barely dent it.

Audio

Record yourself talking and the model listens to the actual audio — this is not “transcribe first, then process the transcript.” It hears the recording directly, which means it can cope with ums, corrections (“actually, scratch that”), and multiple speakers.

Try this: ramble naturally for 20 seconds — “so for the party we need balloons, um, cake obviously, actually no, cupcakes are easier...” Notice whether it keeps the cake or the cupcakes. That's the test a plain transcription service fails.

How this works

The browser records your microphone, and the recording is attached to the same API call used everywhere else on this page — only the attachment type changes. Audio is tokenised at a fixed rate of 32 tokens per second, so a one-minute recording is about 1,900 tokens.

Things to consider:

  • Audio input costs double text input ($0.50 vs $0.25 per million tokens) — still tiny, but it's a real pattern: richer input types cost more.
  • Understanding vs transcription — you can ask for a verbatim transcript, a summary, extracted action items, or the speaker's mood, all from the same recording. The prompt decides.
  • This is one-shot, not conversational — record, send, get an answer. Live back-and-forth voice needs a different API (the Live API), which this Lite model doesn't support.
Cost
32 tokens/second at $0.50/1M — a 1-minute voice note ≈ $0.001. An hour of audio ≈ 6 cents.
Capability
Native listening: speech recognition, meaning, corrections, tone. No real-time conversation, no audio generation.
Context
Up to ~8.4 hours of audio in a single request (one audio file per request).

Video

The richest input: the model watches the frames and listens to the soundtrack together. Walk through a room narrating what you see, and it combines what you said with what the camera saw.

Try this: record 15–30 seconds panning across a bookshelf or pantry while saying things like “we're low on pasta.” Check the results for items you only showed and items you only said — both should appear. Keep it short: video files get big fast.

Video
Or upload a video file
How this works

Same single API call again, with the video file attached. Behind the scenes the model samples the video at about one frame per second and processes the audio track alongside — roughly 300 tokens per second of footage, so a 30-second clip is ~9,000 tokens.

Things to consider:

  • File size is the real constraint, not model ability. Sending straight from the browser caps out around 15–20 MB (a minute or two of phone video). Longer videos need a two-step upload (the Files API) — the model itself can watch up to ~45 minutes with audio.
  • One frame per second means fast-moving detail gets missed. Slow pans work; quick flashes don't.
  • Video is the most token-hungry input — fine per-clip, but this is where cost math starts to matter at scale.
Cost
~300 tokens/second at $0.25/1M — a 30-second clip ≈ $0.002. A 10-minute video ≈ 4–5 cents.
Capability
Combined sight + hearing over time. Great for walkthroughs and demos; misses split-second detail (1 frame/sec sampling).
Context
Model handles ~45 min of video with audio; the browser-upload path here limits you to ~15 MB per clip.

PDF

Give the model a document and it reads it like a person would — layout, tables, headings and all. There's no copy-paste step and no fragile “PDF text extraction” tool; the model looks at each page directly, so even scanned documents work.

Try this: a bank statement, an invoice, a school newsletter, or a product manual. Documents with tables are the best test — pulling clean rows out of a table is genuinely hard for traditional software and routine for this.

How this works

The PDF is attached to the standard call, and the model treats each page somewhat like an image — about 260 tokens per page — which is why scans, stamps, signatures and table layouts all survive. The response schema then forces the findings into your structured list.

Things to consider:

  • This is the highest-value business pattern on this page — “document in, database rows out” replaces a lot of manual data entry. Adapt the schema to your document type: invoice fields, statement transactions, form answers.
  • Scale is generous — up to 1,000+ pages per document and multiple documents per request (50 MB per file via the API).
  • Verify numbers on high-stakes documents — extraction is very good but not certified-accurate; for invoices and statements, spot-check totals.
Cost
~260 tokens/page — a 10-page document ≈ $0.0007. A thousand 10-page documents ≈ 70 cents.
Capability
Document understanding: tables, layouts, scans, handwriting. Reads like a person, outputs like a database.
Context
Up to ~1,000 pages per file, 50 MB per file, 3,000 files per request — whole contracts and reports fit easily.
